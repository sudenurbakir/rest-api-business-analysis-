# User Stories

## 1. Amaç

Bu doküman, sipariş API'sinin kullanıcı ihtiyaçlarını kullanıcı hikayeleri aracılığıyla tanımlar.

## 2. User Stories

| ID    | User Story                                                                                                                              | Öncelik |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| US-01 | Müşteri olarak sipariş oluşturmak istiyorum, böylece ürün satın alma işlemini başlatabilirim.                                           | High    |
| US-02 | Müşteri olarak sipariş bilgilerimi görüntülemek istiyorum, böylece sipariş detaylarıma ulaşabilirim.                                    | High    |
| US-03 | Müşteri olarak sipariş durumumu görüntülemek istiyorum, böylece siparişimin hangi aşamada olduğunu öğrenebilirim.                       | High    |
| US-04 | Müşteri olarak sipariş bilgilerimi güncellemek istiyorum, böylece hatalı bilgileri düzeltebilirim.                                      | Medium  |
| US-05 | Müşteri olarak uygun durumdaki siparişimi iptal etmek istiyorum, böylece devam etmek istemediğim siparişi sonlandırabilirim.            | Medium  |
| US-06 | Sistem yöneticisi olarak geçersiz sipariş isteklerinin reddedilmesini istiyorum, böylece hatalı verilerin kaydedilmesini önleyebilirim. | High    |

## 3. User Story Formatı

Kullanıcı hikayeleri şu formatta yazılır:

**As a [kullanıcı], I want [ihtiyaç], so that [amaç].**

Örneğin:

**US-01**

* Kullanıcı: Müşteri
* İhtiyaç: Yeni sipariş oluşturmak
* Amaç: Satın alma işlemini başlatmak

## 4. BA Notu

User Story, kullanıcının neye ihtiyaç duyduğunu ve bu ihtiyacın neden önemli olduğunu açıklar.

Her User Story, ilgili Acceptance Criteria ile desteklenerek test edilebilir hale getirilir.
